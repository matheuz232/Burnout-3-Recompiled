# R5900 LD / Load64 v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Advance native R5900 startup execution beyond `LD @ 0x00114f08` by adding validated `Load64` IR, portable execution, Windows x64 execution, dispatcher wiring, startup regression coverage, and CI evidence.

**Architecture:** Keep guest memory behind `R5900GuestMemoryAccess`; add only a `read64` callback and `Load64` opcode. Both the reference executor and x64 backend use the same strict 8-byte-aligned, 32-bit-wrapped address semantics and transactional destination commit. The dispatcher adapts `Ps2MemoryMap::read_u64`, admits `Ld`, and preserves exact cache/fault accounting.

**Tech Stack:** C++20, CMake 3.25+, CTest, Windows x64/MSVC 2022 backend, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-07-r5900-ld-v0-design.md`

## Global Constraints

- Windows x64 is the runtime target; portable IR/executor tests remain host-independent.
- Use TDD RED -> GREEN for every production behavior change.
- Effective address is `uint32(low32(rs.low64) + sign_extend16(imm))` with strict 8-byte alignment and no alignment-down.
- `LD $zero,...` still performs the memory read and can fault.
- Successful nonzero destinations replace only `low64`; `high64` is preserved.
- Failed loads do not modify the destination or execute later IR.
- Preserve existing Store32/Store64/Store128 ABI and behavior.
- No interpreter fallback, MMIO expansion, ELF validation relaxation, proprietary game bytes, or reconstructed missing game data.
- CI must use synthetic/public ISA fixtures only; external ELF mode remains opt-in.

```cpp
const auto base = static_cast<std::uint32_t>(state.gpr[base_index].low64);
const auto address = static_cast<std::uint32_t>(base + static_cast<std::int32_t>(offset));
std::uint64_t value{};
if ((address & 7u) != 0u || context.memory.user == nullptr ||
    context.memory.read64 == nullptr ||
    !context.memory.read64(context.memory.user, address, &value)) {
    record_memory_fault(context, R5900IrMemoryAccessKind::Load,
                        instruction.guest_pc, address, 8u);
    return MemoryAccessFailure;

if (destination_index != 0u) {

}
```

- [ ] **Step 3: Implement dispatcher wiring**

```cpp
bool ps2_memory_read64_adapter(void* user,
                               std::uint32_t address,
                               std::uint64_t* value) noexcept {
    if (user == nullptr || value == nullptr) return false;
    const auto loaded = static_cast<runtime::Ps2MemoryMap*>(user)->read_u64(address);
    if (!loaded.has_value()) return false;
    *value = *loaded;
    return true;
}
```

Populate `memory.read64` on every execution-context path, add `Ld` to eligible instructions, and make fault text choose `load` or `store` from `R5900IrMemoryAccessKind`.
