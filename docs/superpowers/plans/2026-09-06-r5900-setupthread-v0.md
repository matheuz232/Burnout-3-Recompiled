# R5900 SetupThread HLE v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement validated explicit-stack HLE for EE `SetupThread` selector `0x3c`, return the supplied stack top in guest `v0`, and let Burnout 3 startup continue past guest PC `0x001001c8`.

**Architecture:** Extend only the production `R5900HostSyscallService`; the generic syscall interface and dispatcher public contract remain unchanged. The service validates five 32-bit ABI inputs transactionally, records one lightweight `R5900SetupThreadContext`, mutates only `GPR2.low64` on success, and leaves automatic-stack mode plus `SetupHeap` unsupported.

**Tech Stack:** C++20, CMake, Visual Studio 2022 x64, CTest, GitHub Actions Windows CI.

**Spec:** `docs/superpowers/specs/2026-09-06-r5900-setupthread-v0-design.md`

## Global Constraints

- Target remains Windows 10/11 x64.
- Selector comes from low 32 bits of GPR3/`v1` and must equal `0x3c`.
- Inputs are low 32 bits of GPR4..GPR8: `gp`, `stack`, signed `stack_size`, `args`, `root_func`.
- v0 supports only `stack != 0xffffffff`.
- `stack == 0xffffffff` returns `Unsupported` with no guest-state, context, or memory mutation.
- `stack_size <= 0` and 32-bit `stack + stack_size` overflow return `Fault` with no partial mutation.
- Success stores `R5900SetupThreadContext` and changes only `state.gpr[2].low64` to zero-extended `stack_top`.
- `state.gpr[2].high64`, every other GPR/FPR/special register, and guest memory are preserved.
- The handler does not set GPR29/`sp`; guest startup code owns `move $sp,$v0`.
- `IR5900HostSyscallService`, `R5900BlockDispatcherOptions`, dispatcher stop reasons, and dispatcher accounting semantics stay unchanged.
- `SetupHeap` (`0x3d`), automatic-stack kernel allocation, scheduler/thread IDs, and full kernel bookkeeping remain out of scope.
- Do not commit proprietary Burnout 3 ELF/ISO bytes or make CI depend on them.
- Do not claim the game boots after this milestone.

std::uint32_t ee_gpr_low32(
    const R5900IrExecutionState& state,

Inside `R5900HostSyscallService::handle`, after raw-instruction validation and `selector` extraction but before the generic unsupported diagnostic, add:

```cpp
if (selector == kSetupThreadSelector) {
    const auto gp = ee_gpr_low32(state, 4u);
    const auto stack = ee_gpr_low32(state, 5u);
    const auto stack_size_raw = ee_gpr_low32(state, 6u);
    const auto stack_size_signed = std::bit_cast<std::int32_t>(stack_size_raw);
    const auto args = ee_gpr_low32(state, 7u);
    const auto root_func = ee_gpr_low32(state, 8u);

    if (stack == std::numeric_limits<std::uint32_t>::max()) {
        return {
            R5900HostSyscallStatus::Unsupported,
            "SetupThread automatic-stack mode is unsupported in v0",
        };
    }
    if (stack_size_signed <= 0) {
        return {
            R5900HostSyscallStatus::Fault,
            "SetupThread explicit stack_size must be positive",
        };
    }
    if (stack > std::numeric_limits<std::uint32_t>::max() - stack_size_raw) {
        return {
            R5900HostSyscallStatus::Fault,
            "SetupThread explicit stack top overflows 32-bit guest address space",
        };
    }

    const R5900SetupThreadContext candidate{
        gp,
        stack,
        stack_size_raw,
        stack + stack_size_raw,
        args,
        root_func,
    };
    setup_thread_context_ = candidate;
    state.gpr[2].low64 = static_cast<std::uint64_t>(candidate.stack_top);
    return {R5900HostSyscallStatus::Handled, {}};
}
```

Leave `memory` unused in this named handler. Leave the existing unknown-selector diagnostic unchanged for all selectors other than `0x3c`.
