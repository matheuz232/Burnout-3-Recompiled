# R5900 SetupThread HLE v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement validated explicit-stack HLE for EE `SetupThread` syscall selector `0x3c`, returning the supplied stack top in guest `v0` and allowing Burnout 3 startup execution to continue past `0x001001c8`.

**Architecture:** Extend the existing production `R5900HostSyscallService` only; the generic syscall boundary and dispatcher interface stay unchanged. The service validates the five 32-bit ABI inputs transactionally, records one lightweight `R5900SetupThreadContext`, mutates only `GPR2.low64` on success, and leaves automatic-stack mode plus `SetupHeap` unsupported.

**Tech Stack:** C++20, CMake, Visual Studio 2022 x64, CTest, GitHub Actions Windows CI.

**Spec:** `docs/superpowers/specs/2026-09-06-r5900-setupthread-v0-design.md`

## Global Constraints

- Target remains Windows 10/11 x64; do not add a non-Windows runtime path for this milestone.
- `SetupThread` selector is read from low 32 bits of GPR3/`v1` and must equal `0x3c`.
- Inputs are low 32 bits of GPR4..GPR8: `gp`, `stack`, signed `stack_size`, `args`, `root_func`.
- v0 supports only explicit stack mode: `stack != 0xffffffff`.
- `stack == 0xffffffff` returns `Unsupported` without state, context, or memory mutation.
- `stack_size <= 0` and 32-bit `stack + stack_size` overflow return `Fault` without partial mutation.
- Successful handling stores `R5900SetupThreadContext` and changes only `state.gpr[2].low64` to zero-extended `stack_top`; `state.gpr[2].high64` and all other architectural state are preserved.
- The syscall handler must not write guest memory and must not set GPR29/`sp`; guest startup code owns `move $sp,$v0`.
- `IR5900HostSyscallService`, `R5900BlockDispatcherOptions`, and dispatcher stop-reason interfaces remain unchanged.
- `SetupHeap` (`0x3d`), automatic-stack kernel allocation, scheduler/thread IDs, and full kernel bookkeeping remain out of scope.
- Do not commit proprietary Burnout 3 ELF/ISO bytes or make CI depend on them.
- Do not claim the game boots after this milestone.

## File Structure

- `src/recompiler/windows/r5900_host_syscall_service.h` — owns the public lightweight SetupThread context type, inspection accessor, and production service state.
- `src/recompiler/windows/r5900_host_syscall_service.cpp` — owns selector dispatch, explicit-stack validation, context commit, and `v0` mutation.
- `tests/r5900_host_syscall_service_windows_tests.cpp` — production-service unit contract including success, transactional failure, state preservation, and context persistence.
- `tests/r5900_block_dispatcher_syscall_windows_tests.cpp` — proves the real production service composes with dispatcher PC/accounting semantics; existing fake-service tests remain for generic boundary behavior.
- `tests/r5900_block_dispatcher_bss_clear_windows_tests.cpp` — startup-shaped integration proving BSS + OR/setup state commits before real SetupThread HLE and the syscall is not compiled/cached.
- `README.md` — user-facing implementation status and exact supported/unsupported SetupThread scope.
- `docs/PROGRESS.md` — milestone status and CI evidence.
- `CMakeLists.txt` — no change expected because all coverage is added to already registered Windows CTest targets.

- [ ] **Step 4: Implement minimal explicit-stack SetupThread handling transactionally**

In `r5900_host_syscall_service.cpp`, add `<bit>` and `<limits>`, define the selector, and branch before the generic unsupported diagnostic:

```cpp
constexpr std::int32_t kSetupThreadSelector = 0x3c;

std::uint32_t ee_gpr_low32(
    const R5900IrExecutionState& state,
    std::size_t index) noexcept {
    return static_cast<std::uint32_t>(state.gpr[index].low64);
}
```

Inside `R5900HostSyscallService::handle`, after validating the raw instruction and extracting `selector`, implement:

```cpp
if (selector == kSetupThreadSelector) {
    const auto gp = ee_gpr_low32(state, 4u);
    const auto stack = ee_gpr_low32(state, 5u);
    const auto stack_size_raw = ee_gpr_low32(state, 6u);
    const auto stack_size_signed = std::bit_cast<std::int32_t>(stack_size_raw);
    const auto args = ee_gpr_low32(state, 7u);
    const auto root_func = ee_gpr_low32(state, 8u);

    if (stack == std::numeric_limits<std::uint32_t>::max()) {
        return {
            R5900HostSyscallStatus::Unsupported,
            "SetupThread automatic-stack mode is unsupported in v0",
        };
    }

    if (stack_size_signed <= 0) {
        return {
            R5900HostSyscallStatus::Fault,
            "SetupThread explicit stack_size must be positive",
        };
    }

    if (stack > std::numeric_limits<std::uint32_t>::max() - stack_size_raw) {
        return {
            R5900HostSyscallStatus::Fault,
            "SetupThread explicit stack top overflows 32-bit guest address space",
        };
    }

    const R5900SetupThreadContext candidate{
        gp,
        stack,
        stack_size_raw,
        stack + stack_size_raw,
        args,
        root_func,
    };

    setup_thread_context_ = candidate;
    state.gpr[2].low64 = static_cast<std::uint64_t>(candidate.stack_top);
    return {R5900HostSyscallStatus::Handled, {}};
}
```

Keep the existing generic unknown-selector diagnostic unchanged for all selectors other than `0x3c`. Do not use `memory` in this handler.
