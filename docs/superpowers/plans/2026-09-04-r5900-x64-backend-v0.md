# R5900 x86-64 Backend v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile the existing R5900 IR v0 subset into executable Windows x86-64 machine code and prove native execution is bit-for-bit equivalent to the reference IR executor for synthetic NOP/ADDU/ADDIU/ORI programs.

**Architecture:** Extract structural IR validation into a portable shared unit first. Add a Windows-only `b3r_recompiler_x64` library containing a move-only executable-block RAII wrapper and a minimal dependency-free byte emitter. The generated function receives `R5900IrExecutionState*` in RCX, uses only volatile RAX/RDX/RCX, mutates only GPR low64 values plus architectural GPR0 normalization, and is checked differentially against `execute_r5900_ir`.

**Tech Stack:** C++20, CMake 3.25+, Win32 `VirtualAlloc`/`VirtualProtect`/`FlushInstructionCache`/`VirtualFree`, MSVC 19.44 / Visual Studio 2022 x64, CTest, GitHub Actions Windows Server 2022.

**Spec:** `docs/superpowers/specs/2026-09-04-r5900-x64-backend-v0-design.md`

## Global Constraints

- Target Windows 10/11 x64 only for native backend execution.
- No LLVM, AsmJit, DynASM, or other code-generation dependency.
- Never request or retain RWX memory; executable pages transition `PAGE_READWRITE -> PAGE_EXECUTE_READ`.
- Generated code may dereference only the caller-provided `R5900IrExecutionState*` at compile-time-known GPR offsets.
- No guest-controlled native addresses, branches, calls, guest memory accesses, stack accesses, or nonvolatile-register modifications.
- Current backend opcodes are exactly `Nop`, `AddWordSignExtend`, and `Or64`.
- Current guest coverage is exactly NOP, ADDU, ADDIU, and ORI through the existing lowering.
- Preserve every GPR `high64` value except architectural normalization of GPR0.
- Validate all IR before executable allocation; failed compilation exposes no partial executable block.
- Keep portable analysis/recompiler builds free of Win32 headers.
- No proprietary Burnout 3 executable or game data may be committed or required by tests.

- [ ] **Step 5: Implement W^X publication**

```cpp
void* code = VirtualAlloc(nullptr, bytes.size(), MEM_RESERVE | MEM_COMMIT, PAGE_READWRITE);

std::memcpy(code, bytes.data(), bytes.size());
DWORD old_protect{};
if (!VirtualProtect(code, bytes.size(), PAGE_EXECUTE_READ, &old_protect)) {
    VirtualFree(code, 0, MEM_RELEASE);
    return protection_failure();

if (!FlushInstructionCache(GetCurrentProcess(), code, bytes.size())) {
    VirtualFree(code, 0, MEM_RELEASE);
    return cache_flush_failure();
}
```

```cpp
void expect_matches_reference(const std::vector<R5900IrInstruction>& program,
                              const R5900IrExecutionState& initial) {
    auto expected = initial;
    auto actual = initial;
    const auto reference = execute_r5900_ir(program, expected);
    expect(reference.ok(), "reference program must execute");

        expect(actual.gpr[i].high64 == expected.gpr[i].high64, "high64 mismatch");

}
```

## Completion Boundary

Completion of this plan proves only:

```text
synthetic R5900 words
        -> production decoder
        -> IR v0 lowering
        -> x86-64 machine-code emission
        -> Windows native execution
        -> exact EE GPR-state comparison against the reference executor
```

It does **not** prove real Burnout 3 ELF execution, control-flow dispatch, memory operations, system emulation, graphics, audio, input, menus, racing, or full-game compatibility.
