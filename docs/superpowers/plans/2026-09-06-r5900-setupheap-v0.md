# R5900 SetupHeap HLE v0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement and CI-validate production `SetupHeap` (`0x3d`) HLE for Burnout 3's main-thread startup path without mutating guest architectural state or guest memory.

**Architecture:** Extend the existing concrete `R5900HostSyscallService` with one lightweight `R5900SetupHeapContext`. `heap_size == 0xffffffff` derives `heap_end` from the committed `SetupThread.stack_base`; positive explicit sizes derive `heap_end = heap_start + heap_size` with overflow/stack-bound checks. The dispatcher, generic host-syscall interface, CMake topology, and generated x64 path stay unchanged.

**Tech Stack:** C++20, CMake, Visual Studio 2022/MSVC x64 Release, GitHub Actions Windows CI, CTest.

**Spec:** `docs/superpowers/specs/2026-09-06-r5900-setupheap-v0-design.md`

## Global Constraints

- Work only on `design/r5900-setupheap-v0` until the user explicitly chooses an integration action.
- Base behavior is integrated `feature/r5900-or-v0` head `b031b39354afa4ea65aa2339f76ceb596e67df61` plus the approved SetupHeap spec/plan commits.
- Do not modify or merge `main`, the PR #22 base branch, or another integration branch during implementation.
- Do not commit proprietary Burnout 3 ELF/data bytes. The lawful `SLUS_210.50` remains external diagnostic input only.
- `SetupHeap` selector is exactly `0x3d`.
- ABI inputs are low32 `GPR4/a0 = heap_start` and low32 `GPR5/a1 = heap_size_raw`.
- Public API semantics are `void SetupHeap(void*, s32)`; success preserves `GPR2/v0` and every other guest architectural field.
- `heap_size_raw == 0xffffffff` means `heap_end = setup_thread_context.stack_base`.
- Positive explicit sizes require signed value `> 0`, no 32-bit unsigned overflow, and `heap_end <= stack_base`.
- SetupHeap requires a previously successful SetupThread context.
- Missing SetupThread, zero size, negative size other than `-1`, overflow, automatic-size `heap_start >= stack_base`, and explicit overlap past `stack_base` are transactional `Fault`s.
- Success mutates only host-side `setup_heap_context_`; no guest GPR/special-register/FPR/memory mutation is allowed.
- A later valid SetupHeap atomically replaces the prior heap context; later fault/unsupported calls preserve it.
- A later successful SetupThread invalidates stale heap context only after SetupThread validation succeeds; failed/unsupported SetupThread preserves it.
- `EndOfHeap 0x3e`, allocators, scheduler/thread manager, automatic-stack SetupThread, graphics, DMA/IOP, audio, input, menu, and gameplay are out of scope.
- Keep `IR5900HostSyscallService`, `r5900_block_dispatcher.h/.cpp`, and CMake target topology unchanged unless a failing test proves the approved design impossible. If that occurs, stop and revise the design.
